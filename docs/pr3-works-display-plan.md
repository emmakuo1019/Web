## 1. 目標與設計策略

**目標 A：首頁只展示精選作品。** 將目前首頁一次顯示全部作品的 Grid 改為上下兩排作品帶。上排向左、下排向右慢速連續移動，設立清楚的 **VIEW ALL WORKS** 入口。

**目標 B：建立完整作品總覽。** 新增 `works.html`，以靜態網格呈現全部作品，頁面上方設分類篩選（ALL、GAME、VISUAL、3D、INTERACTIVE；名稱與分類需依新增作品清冊再審核）。全站導覽維持 HOME / WORKS / PROFILE / CONTACT，分類不塞進主導覽列。

**目標 C：同一份作品資料支援三種視圖。** 保留 `data/projects.json` 作為唯一作品清冊；首頁精選、作品總覽、`project.html?id=...` 詳細頁共用資料，讓後續新增作品不需重複維護。

設計限制：
- 維持大字標題、米白／深色雙主題、黑色細框線、節奏分明的平面編排語言，不套用通用電商輪播模板。
- 作品本身是視覺主體；不新增大量陰影、浮動按鈕或與 Bug 先生競爭注意力的動效。
- 不為了讓跑馬燈「看起來很多」而無限制複製少量的不同作品。
- 「首頁精選」由創作者指定，不依最新年份自動選取；應有設計類型、圖像明暗、構圖尺度的策展平衡。

## 4. 首頁雙排跑馬燈

### 4.1 版面與風格
- 上／下兩條橫向排列；相鄰卡片以細線分隔，保留使用者設計稿的版面節奏。
- 作品卡資訊順序：**年份 → 標題 → 圖片**；類別可視需要低調補充，避免文字資訊過量。
- 初始卡寬約 **190–280 CSS px**，依內容及裝置調整；圖片建議先以 **4:3** 一致比例評估，`object-fit` 不可裁掉重要畫面。
- 作品帶可在視覺上橫向突破原本 `1200px` 主容器，但頁面本身**不可新增水平捲軸**。
- 不以重複相同縮圖冒充不同作品；特別檢查相鄰卡之圖像差異、標題長度、明暗節奏。

### 4.2 自動移動（精確指標桌面）
- 上排向左、下排向右，**連續等速（linear）**，不採每張停靠的傳統 carousel。
- 初始設計速度建議 **18–28 CSS px/s**，兩排可略有速度差；最終以人工閱讀性測試調整。
- 滑鼠移入一排就暫停**該排**；鍵盤焦點進入也須暫停並維持作品可見。
- 分頁隱藏或區塊不可見時，盡量停止不必要動畫；恢復不可突然跳位或累積多個動畫迴圈。
- 行動網頁、主要觸控介面、`prefers-reduced-motion: reduce`：**停用自動移動**，提供原生水平手動捲動。
- 無動畫、JS 未完成或資料少的情境仍需能看到作品和完整連結，禁止空白首頁。

### 4.3 無縫循環與可操作性（PR3-03 必須先審核方案）
無限循環在內容寬度不足時可能出現空白；不得直接使用固定兩份複本而忽略實際內容寬度。實作前需提出：
1. 每排不足一個可視寬時如何處理（按內容寬度重複補齊，或退回靜態作品列）；**不必為少量作品強行啟用動畫**。
2. 如何依實際量測處理圖片載入、字型、resize 與不同卡寬，使循環邊界沒有跳格。
3. 如何避免「複製卡」被螢幕閱讀器朗讀兩次、造成重複 Tab 目標，且畫面中可見的卡片仍能以指標開啟原作品。
4. 鍵盤焦點進入動態作品帶時，如何切換到穩定可水平捲動模式或確保聚焦卡完整可見。不得讓焦點停留在不可見的移動卡片。
5. 禁止透過克隆互動元素造成重複 ID；不可僅對含可聚焦子項的克隆加 `aria-hidden` 就宣稱可及性完成。

**驗收不只看「會動」，而是看所有作品在移動、暫停、鍵盤與觸控下都可實際開啟。**

### 4.4 手機及減少動態
- 手機先採 CSS 橫向溢出捲動，可考慮 `scroll-snap-type: x proximity`，但不得造成無法離開作品列的捲動體驗。
- 允許單指橫滑作品；垂直捲整頁不受阻，避免自訂 touchmove 全域攔截。
- 兩排仍呈現，但皆採可手動滑動的靜態作品帶。
- 以實際媒體查詢、操作方式和測試結果決定模式，不能只靠某一個 User-Agent。
- 減少動態時禁止自動播放，且靜態卡片完整可閱讀；不要用停用動畫的 CSS 同時隱藏整排。

## 5. 作品資料結構與清冊

**唯一來源：`data/projects.json`。** 原有 `id`、`title`、`description`、`cover`、`view`、`type`、`designer`、`teacher`、`year`、`hold` 保持相容；`link` 欄位先盤點實際用途。

新增／擴充欄位（名稱為本次建議規格）：

| 欄位 | 型態 | 契約 |
| --- | --- | --- |
| `category` | string | 單一主要分類，必須是允許的分類鍵 |
| `tags` | string[] | 跨領域技術／媒材標籤；初版只記錄，不開放複合篩選 |
| `featured` | boolean | 是否進入首頁；未指定視為 false，遷移時明確填寫 |
| `featuredRow` | 1 或 2 | 精選作品所在列；僅在 featured=true 時必填 |
| `featuredOrder` | number | 該列排序；同列不得有不明確的重複順位 |
| `sortOrder` | number（選填） | 全量清冊同年份下的人工順序 |

分類鍵初稿：`game`、`visual`、`3d`、`interactive`。對外標籤初稿：GAME、VISUAL、3D、WEB / INTERACTIVE。只呈現有作品的分類，不創建空分類。若新作品明確需要其他類型，先更新分類對照規格而不是在每個頁面硬編碼。

資料遷移要求：
- `id` 是公開網址一部分，現有 6 件作品的 ID 不可隨意更換。
- 原本 `title` 包含 `<br>`；提出單一「顯示用純文字／排版斷行」處理策略，避免任意使用 `innerHTML` 插入未處理內容。
- 年份目前是字串；排序須按數值化年份處理，無效年份要有穩定排序規則。
- 缺圖、重複 ID、無效分類、缺失必填欄位、錯誤 featuredRow／featuredOrder 須被驗證工具或測試清單找出。
- 列表、總覽、詳細頁不得各自維護一份作品陣列。
- `link="#"` 不代表真實展示網址，不生成會把人導回本頁頂部的無效外部 CTA。
- 新增作品依實際圖片／文字素材進行，**不得由 AI 虛構作品、年份、獎項或製作貢獻**。

### 5.1 素材與收錄門檻
每件新作品至少提供：穩定 ID、正式名稱、年份、主要分類、封面／縮圖、作品說明、個人或團隊貢獻與適當署名。資料不完整可先維持不精選；若無法安全呈現詳細頁，則先不公開收錄。

目前僅有 6 筆舊作品且部分圖片路徑重複。首頁設定 6–10 件是**策展目標而非上線硬性數字**；PR3-01 應先確認可用且視覺差異足夠的作品數。每排不足以形成良好連續效果時，必須有靜態降級方案。

## 6. 作品總覽頁與分類操作

- 預設 **ALL**：全部作品，依年份新到舊；同一年依 `sortOrder` 或穩定原始順序。
- 選擇分類即時篩選，不重載整頁、不改作品 ID。
- 分類控制使用原生 `button type="button"`、可見 `:focus-visible`，使用 `aria-pressed` 呈現選取狀態；不要求建立不符合語意的 tablist。
- 切換類別時焦點留在按鈕，避免焦點突然跳到列表末端。
- 對符合數量提供可理解回饋；無結果顯示空狀態，不要只出現空白。
- 載入中、JSON 讀取失敗、資料為空、某張圖片失敗時各有可讀降級，不使整頁崩潰。
- 卡片整張可點擊，圖片比例、標題及年份有一致規則；分類列可在 320px 裝置下折行或橫向捲動，不能溢出整個頁面。

## 9. 驗收矩陣

### A. 作品與資料
- 原有 6 件作品各自可正確開啟；新增作品也使用穩定 `id`。
- 精選／非精選切換與上下排排序符合使用者設定。
- 分類不誤收、不遺漏，ALL 顯示所有應公開作品。
- 缺圖／不合法 JSON／未知 `id` 不造成未處理例外。

### B. 跑馬燈
- 桌面兩排朝相反方向等速移動；一個完整循環無白縫、突然回彈。
- 每個可見作品卡可開啟對應作品；暫停／恢復不重建多個動畫。
- 滑鼠懸停、鍵盤進入時能停下，聚焦作品仍在可視範圍。
- 手機可橫滑且不妨礙縱滑；Reduced Motion 下不自動移動。
- 不足量作品、圖片晚載入、resize 和離開頁面再返回時可安全降級。

### C. 作品總覽
- 320／375／390／768／1280／1440 CSS px、短橫向、200% 瀏覽器縮放。
- ALL 及每個有效分類、無結果、載入失敗、圖片失敗。
- 分類按鈕原生鍵盤操作與可視焦點；無新增整站水平捲軸。
